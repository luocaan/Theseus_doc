模组 API 参考

com.seecmd.mod.api 全部接口的签名定义与行为契约（唯一权威签名）

适用版本：v2（当前实现） 文档语言：中文 对应包：com.seecmd.mod.api（含子包 context / render / capability / judge / event）+ com.seecmd.mod.api.spi

文档定位：本文是 SEECMD 模组 API 的唯一权威签名定义。所有接口均已落地（标注 @Experimental 预览版），接口签名以本文为准。@Experimental 标注表示「实现中，可能调整」，正式发布前可能微调。

0. 接口状态约定

本文档中所有接口标注 @Experimental（实现中，可能调整）。

状态含义
可用接口已实现并接入核心循环，签名以本文为准
受限接口已实现，可注册/查询/遍历，但核心循环对其回调的派发尚不完整（当前版本无此类接口；如未来出现将在此标注）
� 已定义接口已定义，但宿主尚未注入实现，运行期调用返回空或不生效

1.2 包依赖说明

模组编译期仅依赖 com.seecmd:mod-api 瘦身 jar，该 jar 仅含 com.seecmd.mod.api.* 与 com.seecmd.mod.api.spi.*，从物理上隔离了 API 与宿主/内核。模组代码按需 import 标准库类（java.* / java.util.* / java.nio.file.* 等），java.awt.Color 作为纯值对象允许使用。

2.7 Notifier

可用。包：com.seecmd.mod.api。经 ModContext.notifier() 获取，向玩家展示信息。所有方法可在任意线程调用（仅入队后立即返回），渲染由游戏线程统一完成。

方法签名说明
void info(String message)显示普通提示（toast，约 4 秒后自动消失）
void warning(String message)显示警告（toast，约 4 秒后自动消失）
void error(String message)显示错误（toast，约 4 秒后自动消失）
void dialog(String message, int timeoutMs)显示屏幕中央的定时弹窗，到期自动关闭。同一时刻宿主只显示一个，后调用的覆盖先前的
java
// 在 onLoad 或任意事件回调中
ctx.notifier().info("模组已加载");
ctx.notifier().warning("检测到旧版配置文件");
ctx.notifier().error("音频资源缺失");
ctx.notifier().dialog("本模组需要游戏 v0.7.0+", 5000);

toast 有同屏数量上限，频繁调用会丢弃最旧消息；逐帧刷新的调试输出请用 getLogger()，不要用 notifier。

3. 注册表

3.1 通用约定

  • 所有注册项 id() 使用命名空间格式 <modId>:<name>（如 seecmd:hold、mymod:slide）。
  • 注册时机：进程级，在 Mod.onLoad(ModContext) 中注册一次。
  • 重复注册被忽略并告警。
  • 每个回调方法独立异常隔离。

3.2 NoteTypeDefinition + NoteTypeRegistry

包：com.seecmd.mod.api.spi。 可用。

接入程度差异：谱面解析已接入（加载时按序列化 key 注入 typeDef），音符行为判断（isBarrier/isHold/isExploit/isPayload）已委托给定义对象；判定与渲染回调已接入核心循环——音符被判定时宿主调用 onJudge()，定义对象可通过 sink.accept(kind, time) 产出自定义判定等级；渲染时宿主对自定义类型调用 render() 由其自绘（内置类型不派发，保持内核渲染不变）。回调抛异常会被宿主捕获并回退内置逻辑，不影响游玩。外观已支持按类型定制——皮肤系统可为其提供专属槽位（图片皮肤放 <类型key>.png、字符皮肤在 note.json 加 custom 映射，见资源制作指南），未提供专属外观时回退到行为分类对应槽位。

配套类型（NoteTypeDefinition 引用的输入/上下文接口）：

java
/** 运行时音符基类（api 侧）。自定义音符类型继承此类，不可直接依赖内核模型。 */
public abstract class NoteData {
    // --- 读取（运行时只读） ---
    /** 音符时间（毫秒）。 */
    long time();
    /** 所在轨道（0-based）。 */
    int lane();
    /** 音符类型 key（与 NoteTypeDefinition.serializationKey() 对应，宿主填充）。 */
    String typeKey();
    /** 长音符结束时间；非长音符返回 null。 */
    Long endTime();
    /** 音符是否已被判定。 */
    boolean isJudged();
    /** 运行时扩展数据（宿主/模组可读写，不参与序列化）。 */
    Object extensionData();

    // --- 解析期写入（deserialize / onCreateRuntime 中调用） ---
    void setTime(long time);
    void setLane(int lane);
    void setEndTime(Long endTime);
    void setJudged(boolean judged);
    void setExtensionData(Object data);
}

/** 判定输入：音符到达判定线时宿主提供的判定上下文。 */
public interface JudgeInput {
    /** 音符时间（毫秒）。 */
    long noteTime();
    /** 判定时间（毫秒，一般为当前音乐时间）。 */
    long judgeTime();
    /** 时间差（judgeTime - noteTime，正值=迟到，负值=早到）。 */
    long deltaMs();
    /** 音符所在轨道。 */
    int lane();
    /** 是否为长音符结尾判定。 */
    boolean isHoldEnd();
    /** 运行时音符数据。 */
    NoteData note();
}

/** 判定结果收集器：定义对象调用 accept 产生判定结果。 */
@FunctionalInterface
public interface JudgeSink {
    void accept(JudgmentKindDefinition kind, long judgeTime);
}

/** 谱面解析上下文（仅用于 deserialize/onCreateRuntime）。 */
public interface NoteParseContext {
    int totalLanes();
    int bpm();
    double contentScale();
}

/** 音符渲染上下文（每帧 render 传入）。 */
public interface NoteRenderContext {
    /** 音符在 canvas 上的 x 坐标。 */
    double x();
    /** 音符在 canvas 上的 y 坐标（基于音乐时间偏移）。 */
    double y();
    /** 音符宽度（基于轨道宽度）。 */
    double width();
    /** 当前音乐时间偏移（毫秒，用于动画）。 */
    long musicTimeMs();
    /** 音符所属轨道索引。 */
    int lane();
    /** 是否为长音符结尾。 */
    boolean isHoldEnd();
}
java
public interface NoteTypeDefinition {
    /** 唯一标识（命名空间格式，如 "mymod:slide"）。 */
    String id();

    /** 显示名称（如 "滑键"）。 */
    String displayName();

    /** 谱面 JSON 中的序列化 key（如 "slide"）。 */
    String serializationKey();

    /**
     * 谱面解析时调用：从 JSON 对象创建运行时音符。
     * @param json   谱面 JSON 中该音符的完整对象
     * @param ctx    解析上下文（含轨道数、BPM 等）
     * @return 运行时音符数据（NoteData 或自定义子类）
     */
    NoteData deserialize(JsonObject json, NoteParseContext ctx);

    /**
     * 解析完成后调用：补充运行时字段（如关联查找、默认值填充）。
     * @param note 已由 deserialize 创建的运行时音符
     */
    default void onCreateRuntime(NoteData note) {}

    /**
     * 判定回调：音符到达判定线时调用。
     * @param input  判定输入（时间差、轨道等）
     * @param sink   判定结果收集器（调用 sink.accept(judgment, time) 产出结果）
     */
    void onJudge(JudgeInput input, JudgeSink sink);

    /**
     * 每帧渲染回调。
     * @param canvas   模组唯一绘制入口
     * @param ctx      渲染上下文（含音符位置、时间偏移、轨道等）
     */
    void render(RenderCanvas canvas, NoteRenderContext ctx);

    // --- 生命周期回调（默认空实现） ---
    /** 音符被判定后调用。 */
    default void onJudged(NoteData note, JudgeResult result) {}

    /** 音符被移除（超时/销毁）时调用。 */
    default void onRemoved(NoteData note) {}
}

public interface NoteTypeRegistry {

    NoteTypeDefinition get(String id);
    Collection<NoteTypeDefinition> getAll();

4. 能力接口

所有能力接口位于 com.seecmd.mod.api.capability。每个接口按「读数据 / 改状态 / 渲染覆盖」三件套组织。能力实例在 Mod.onLoad 中通过 ModContext.capabilities() 注册。

� 接入状态：GameplayHud / GameStateAccess / SceneHost / AudioAccess / InputAccess / StoryAccess / ModManagerAccess 均已接入主循环，capabilities().get(Xxx.class) 返回可用实例。其中前 6 个能力仅游玩场景内可用，ModManagerAccess 为进程级能力（任何场景、任意时刻可用）。

能力注入注册表 CapabilityRegistry（包：com.seecmd.mod.api.capability。 可用）：

java
/** 能力注入注册表入口。 */
public interface CapabilityRegistry {
    /** 注册能力实例（如 GameplayHud、GameStateAccess）。 */
    <T> void register(Class<T> type, T instance);

    /** 按类型获取已注册能力。 */
    <T> T get(Class<T> type);
}

宿主按类型注入能力：模组注册 GameplayHud.class 的实例，宿主在每个游玩场景读取可用能力，模组用 get(Class) 取用。

4.1 GameplayHud

可用。游玩 HUD 控制。覆盖语义：宿主先查 setXxxVisible(false)，被覆盖则不画原版。

包归属：GameplayHud 位于 com.seecmd.mod.api.capability；其配套类型 HudValues / HudContext 位于 com.seecmd.mod.api.context，RenderLayer 枚举位于 com.seecmd.mod.api.capability。

java
public interface GameplayHud {
    /** 读取 HUD 数值。 */
    HudValues values();

    // --- 可见性开关（覆盖机制） ---
    void setProgressVisible(boolean visible);
    void setComboVisible(boolean visible);
    void setScoreVisible(boolean visible);
    void setAccuracyVisible(boolean visible);

    /** 覆盖渲染：宿主在覆盖阶段调用。只在有组件被隐藏时调用。 */
    void renderOverlay(RenderCanvas canvas, HudContext hudCtx);
}

/** 引擎内置渲染阶段枚举（自底向上，每层有固定数字编号 index()，数字越大越靠上）。 */
enum RenderLayer {
    BACKGROUND(0),  // 第 0 层：背景（模组背景渲染器，位于游玩内容之下）
    NOTES(1),       // 第 1 层：轨道 / 音符
    JUDGE_FX(2),    // 第 2 层：判定特效
    HUD(3),         // 第 3 层：原版 HUD
    OVERLAY(4),     // 第 4 层：覆盖渲染（renderOverlay）
    FULLSCREEN(5);  // 第 5 层（最顶层）：全屏覆盖层（后处理滤镜）

    /** 本层的数字编号（自底向上，0 为最底层）。 */
    int index();
}

// 模组内容的叠放不限于 0-5：RenderFilter / BackgroundRenderer 的 zOrder()
// 接受任意整数层号，越大越靠上（如 -99 压到最底、99 提到最顶），
// 只在各自插槽（背景 / 滤镜）内排序。详见 5.4 节与 5.6 节。

/** HUD 数值只读视图。 */
public interface HudValues {
    double progress();          // 游玩进度 0-1
    int combo();
    int maxCombo();
    int score();
    double accuracy();          // 准度 0-1
    long musicTimeMs();
    int perfects();
    int greats();
    int misses();
}

/** 覆盖渲染上下文。 */
public interface HudContext {
    RenderLayer layer();        // 当前渲染阶段
    int zOrder();               // 覆盖层 z 顺序
}

4.7 ModManagerAccess

可用。模组管理能力，供第三方开发「模组菜单」类模组使用。与其它能力不同，它是进程级能力：在 onLoad 中经 capabilities().get(ModManagerAccess.class) 取用后，任意场景、任意时刻均可查询已注册模组的状态，或运行时启用 / 停用模组（立即生效并持久化，与内置模组管理界面行为一致）。

public interface ModManagerAccess {

    /** 按 id 查询模组元信息（未注册返回 null）。 */
    ModInfo getModInfo(String modId);

    /** 当前启用模组 id 列表（含内置模组）。 */
    List<String> enabledMods();

    /** 该模组是否已加载激活（ACTIVE）。 */
    boolean isActive(String modId);

setEnabled 会立即激活 / 卸载对应模组（onLoad / onUnload 会随之触发），请确认目标模组启停安全后再调用；停用当前正在使用的模组可能导致其注册内容在本次会话内失效。

5.7 HitEffectStyle（打击特效）

可用。包：com.seecmd.mod.api.render。经 GameplayMod.registerHitEffectStyles 注册 provider，判定时宿主按注册顺序取第一个非 null 的样式并渲染。支持文本与图片序列两种效果，本次版本新增两种能力：

  • 自动帧时长：不写每帧时长，只写总持续时间 durationMs()，每帧长度 = durationMs / 帧数 自动均分，适配帧数不固定的特效。
  • 精灵图拆帧：提供一张精灵图（sprite sheet）+ 每格分辨率（cellWidth / cellHeight），宿主按从左到右、从上到下的顺序将网格拆为播放帧，省去手动切图。
java
public interface HitEffectStyle {
    /** 效果总时长（毫秒）。 */
    long durationMs();

    /** 显式每帧时长（毫秒）。返回 <= 0 表示启用自动均分（见 autoFrameDuration）。 */
    long frameDurationMs();

    /** true = 每帧时长 = durationMs / 帧数，自动分配。 */
    default boolean autoFrameDuration() { return frameDurationMs() <= 0; }

    /** 精灵图。非 null 时 frames() 被忽略，按 cellWidth/cellHeight 网格拆帧。 */
    default RenderImage sheetImage() { return null; }

    /** 精灵图每格宽（像素）。 */
    default int cellWidth() { return 0; }

    /** 精灵图每格高（像素）。 */
    default int cellHeight() { return 0; }

    /** 显式帧列表（仅 sheetImage() 返回 null 时使用）。 */
    List<RenderImage> frames();

    /** 是否循环播放。 */
    boolean loop();

    /** 绘制缩放（1.0 = 原始大小）。 */
    float scale();
}

图片规格

项目规格
格式PNG（保留透明通道）；经 RenderResources.loadImage(path) 加载，path 相对模组数据目录或 jar 内资源
尺寸无固定分辨率限制。绘制大小 = 图片分辨率 × scale()；分辨率越高画面越精细，但请控制总像素量（特效每帧都要绘制）
锚点以判定点为中心水平居中：绘制X = 轨道中心 − 绘制宽/2，绘制Y = 判定线 − 绘制高/2
透明度整体透明度 = 判定强度（0~1），并随生命周期淡出。图片自身 alpha 通道参与合成
播放非循环播完停最后一帧；循环则重复播放。帧时长 = autoFrameDuration() ? max(1, durationMs / 帧数) : max(1, frameDurationMs())
精灵图切片网格宽高为 cellWidth / cellHeight，按从左到右、从上到下拆帧；不满一格的多余像素被忽略；单格尺寸不得超过整图
精灵图加载失败回退到显式帧列表；帧数取两者较小值

� 图片不需要按轨道宽度设计——特效以固定分辨率绘制并整体缩放，与音符皮肤的「按轨道等比缩放」不同。

生命周期差异：

  • 全局事件总线（ModContext.globalEventBus()）：进程级，整个游戏生命周期内有效。跨场景订阅（如菜单、选歌、结算）使用此总线。

附录 B：版本与兼容性

  • 本文档对应的 v2 实现为 @Experimental 预览版，后续版本将移除 @Experimental 标注。

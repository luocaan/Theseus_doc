快速上手

从零开始：创建项目 → 编写最小模组 → 打包 → 加载到游戏

什么是 SEECMD 模组

SEECMD 模组系统允许你用 Java 为游戏编写扩展。模组可以：

  • 注册新内容：自定义音符类型、游戏模式、判定等级、谱面扩展段
  • 覆盖渲染：隐藏原版 HUD 组件并在画面上自绘
  • 修改判定：调整判定窗口、改写判定结果、注册新的判定等级
  • 监听事件：订阅游玩事件（判定、连击、开始/结束）与全局事件
  • 控制游戏状态：暂停/恢复/变速/跳转、压入自定义场景、播放音效

所有 API 位于 com.seecmd.mod.api 包中，标注 @Experimental（实现中，可能调整）。

前置条件

  • JDK 17+
  • Maven 或 Gradle
  • mod-api jar：从 Theseus 文档站 直接下载，安装到本地 Maven 仓库后按坐标引用（见下文）

1. 创建项目

创建一个标准 Java 项目，引入 mod-api 依赖。

重要：依赖 scope 必须为 provided（Maven）或 compileOnly（Gradle）。API 由宿主在运行期提供，模组 jar 不得把宿主类打进去。

Maven 示例：

xml
<dependencies>
    <dependency>
        <groupId>com.seecmd</groupId>
        <artifactId>mod-api</artifactId>
        <version>0.6.7</version>
        <scope>provided</scope>
    </dependency>
    <dependency>
        <groupId>com.google.code.gson</groupId>
        <artifactId>gson</artifactId>
        <version>2.10.1</version>
        <scope>provided</scope>
    </dependency>
</dependencies>

Gradle 示例：

groovy
dependencies {
    compileOnly 'com.seecmd:mod-api:0.6.7'
    compileOnly 'com.google.code.gson:gson:2.10.1'
}

包依赖说明

模组编译期仅依赖 com.seecmd:mod-api 瘦身 jar，该 jar 仅含 com.seecmd.mod.api.* 与 com.seecmd.mod.api.spi.*，从物理上隔离了 API 与宿主/内核。java.awt.Color 作为纯值对象允许使用；绘制统一走抽象 RenderCanvas，不接触任何平台图形 API。

2. 编写最小模组

最小模组只需实现 Mod 接口，提供 info() 元信息，并按需覆写 onLoad(ModContext)。

java
package com.example.helloworld;

import com.seecmd.mod.api.Mod;
import com.seecmd.mod.api.ModContext;
import com.seecmd.mod.api.ModInfo;

import java.util.List;

public class HelloWorldMod implements Mod {

    @Override
    public ModInfo info() {
        return ModInfo.of(
                "com_example_helloworld",   // id：小写下划线
                "Hello World",              // 显示名
                "0.1.0",                    // 版本
                List.of("Alice"),           // 作者
                "最小模组示例"               // 描述
        );
    }

    @Override
    public void onLoad(ModContext ctx) {
        // 模组被启用时调用一次
        ctx.getLogger().info("Hello World 模组已加载");
        ctx.getLogger().info("数据目录: " + ctx.getDataDir());
    }
}

关键点

  • Mod.info() 是唯一必须实现的方法，返回模组的 id、名称、版本、作者、描述。
  • onLoad(ModContext) 在模组被启用时调用一次，可读取配置、初始化资源、注册内容。
  • ModContext 是模组的「工具箱」：读取日志（getLogger()）、数据目录（getDataDir()）、配置（config()）、注册表（noteTypes() / gameModes() / judgmentKinds() / chartExtensions()）、能力（capabilities()）。
  • 需要参与游玩（覆盖渲染 / 修改判定 / 监听事件）时，改实现 GameplayMod 接口（继承自 Mod）。

3. 打包

模组编译后打包为标准 jar，必须包含 META-INF/MANIFEST.MF。Seecmd-Mod-Class 声明入口类，游戏加载器据此实例化模组。

manifest
Manifest-Version: 1.0
Seecmd-Mod-Id: com_example_helloworld
Seecmd-Mod-Class: com.example.helloworld.HelloWorldMod
Seecmd-Mod-Name: Hello World
Seecmd-Mod-Version: 0.1.0
Seecmd-Mod-Authors: Alice
Seecmd-Mod-Description: 一个示例模组，演示 SEECMD 模组 API 基础用法

Maven 打包配置：

xml
<build>
    <plugins>
        <plugin>
            <artifactId>maven-jar-plugin</artifactId>
            <configuration>
                <archive>
                    <manifestEntries>
                        <Seecmd-Mod-Id>com_example_helloworld</Seecmd-Mod-Id>
                        <Seecmd-Mod-Class>com.example.helloworld.HelloWorldMod</Seecmd-Mod-Class>
                        <Seecmd-Mod-Name>Hello World</Seecmd-Mod-Name>
                        <Seecmd-Mod-Version>0.1.0</Seecmd-Mod-Version>
                        <Seecmd-Mod-Authors>Alice</Seecmd-Mod-Authors>
                        <Seecmd-Mod-Description>一个示例模组，演示 SEECMD 模组 API 基础用法</Seecmd-Mod-Description>
                    </manifestEntries>
                </archive>
            </configuration>
        </plugin>
    </plugins>
</build>

打包时注意：不要把宿主类打进模组 jar（依赖 scope 用 provided）。模组自身的资源文件（图片、配置模板等）正常打入 jar resources 即可。

4. 加载到游戏

  1. 把打包好的 xxx.jar 放进游戏工作目录下的 mods/ 文件夹（与 data/ 同级）。
  2. 启动游戏，加载器自动扫描 mods/ 目录，读取 manifest 定位入口类并注册。
  3. 模组数据目录在 data/mods/<modId>/（首次访问自动创建）。
  4. 启用状态持久化在 data/settings.json 的 enabledMods，也可用外置工具 mods/mod-manager.jar 管理。

模组 id 命名规范

  • 小写下划线，如 com_example_helloworld。
  • 不得以 builtin_ 开头（保留给内置模组）。
  • 建议使用反向域名前缀避免冲突。
